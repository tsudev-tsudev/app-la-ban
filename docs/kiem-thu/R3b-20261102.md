# R3b - E2E + kịch bản bảo mật nội bộ trên máy thật (02/11/2026)

Thiết bị: Galaxy M32 (SM-M325FV), Android 13, qua `adb.exe` Windows (USB). Bản thử: APK GitHub Release beta.7 -> beta.13
(arm64, ký khoá upload) + bản build thử prod cùng mã nguồn nhánh `phase/r3b`. Không dán bí mật / PII; id thiết bị chỉ ghi
10 ký tự đầu.

## 1. E2E trên M32

- Cài mới beta.7 -> màn giới thiệu + đồng ý -> đăng ký thiết bị prod (attest mức `device`, trạng thái `clean`).
- Banner "Đã có phiên bản mới - beta.13" hiện đúng trên beta.7 (CDN `latest.json`).
- Điểm mốc `R3bMoc8` tạo ở beta.8 (vị trí thật ±20 m), còn nguyên qua beta.9 -> 13.
- Chia sẻ: App Link `compass.tsudev.com/w/<token>` (miền đã `verified`) mở thẳng app, cold start 629 ms, đúng tên + toạ độ
  + hạn link. Token bị sửa 1 ký tự khi mở nguội -> "Link không hợp lệ hoặc bị cắt mất khi gửi.".
- **Lỗi đã sửa:** app đang mở màn "Điểm được chia sẻ" mà nhận link /w/ thứ hai thì vẫn hiện nội dung cũ (go_router giữ `State`
  khi chỉ đổi tham số đường dẫn; `_kq` tính một lần). Sửa: `ValueKey(token)` ở route + widget test (đỏ khi bỏ bản sửa).

## 3. Remote Config `toiThieu` + rollback

Chạy trên **staging** (bản `com.tsudev.laban.stg` build 13 cài cạnh bản prod): đẩy cấu hình prod bị chế độ auto chặn
(thay đổi ảnh hưởng người dùng thật -> cần người dùng duyệt), staging cùng mã + cùng khoá ký `app-1`.

| Bước | Lệnh | Kết quả trên M32 |
|---|---|---|
| Sao lưu | `wrangler kv key get app-cau-hinh --env staging` | `toiThieu` 1, 5 pin |
| Ép | `ky-cau-hinh.mjs dua-len-app --env staging --toi-thieu 14 --khuyen-nghi 14 --pin mac-dinh` | mở lại -> màn "Cần cập nhật ứng dụng" (chặn toàn app) |
| Phát lại gói CŨ (tấn công lùi cấu hình) | đặt lại nguyên văn gói sao lưu (chữ ký hợp lệ, `phatHanh` cũ hơn) | vẫn màn ép - app từ chối gói cũ hơn gói đang giữ |
| Rollback | ký gói MỚI `--toi-thieu 1` | mở lại -> la bàn bình thường |

Kết luận runbook (`ung-pho-su-co.md`): rollback phải ký gói mới (không đặt lại gói cũ) - đúng thiết kế chống lùi.

## 4. Kịch bản bảo mật nội bộ (SEC-TEST)

| Kịch bản | Cách làm | Ghi nhận | Từ chối |
|---|---|---|---|
| APK đóng gói lại | Thêm tài sản + ký lại bằng khoá RSA lạ (zipalign + apksigner) | `ATTEST_FAIL` (Play Integrity `UNRECOGNIZED_VERSION`, lý do `chung-chi`) + `APP_REPACKAGED` -> điểm 120 -> `DEVICE_BANNED` trong ~5 s | màn khoá + REF, mọi lần đăng ký lại 403 (sau bản sửa) |
| Phát lại nonce | `tools/thu/dinh-danh-e2e.mjs` (staging) | - | 401 `nonce` |
| Sửa thân sau ký | như trên, đổi `severity` sau khi ký | - | 401 `chu-ky` |
| Lệch giờ 61 s / khoá khác / thiếu chữ ký / token cũ sau xoay | như trên | - | 401 `lech-gio` / `chu-ky` / `can-chu-ky` / `phien-thu-hoi`; refresh cũ trong ân hạn 409 |
| Giả vị trí | `cmd location providers` test provider (Hoàn Kiếm) | `MOCK_LOCATION` (+20) từ freeRASP; thêm nguồn thứ hai `Location.isMock` trong `location_feature` (chỉ báo, server quyết) | - (chỉ tín hiệu, theo Q8) |
| Proxy chặn giữa | mitmproxy (localhost 8099 qua `adb reverse`) đặt làm proxy hệ thống | App KHÔNG đi qua proxy hệ thống (Dart `HttpClient` + `SecurityContext` chỉ tin 5 CA ghim); kết nối tới API vẫn đi thẳng, không lộ nội dung | pin + network security config không tin CA người dùng |

Tỷ lệ: 5/5 kịch bản có tín hiệu / bị chặn (>= 95 %), 100 % request nhạy cảm không hợp lệ bị từ chối (14/14 bước staging).

**Lỗi High đã sửa (Q51):** bản đóng gói lại bị server cấm nhưng mở lại sau khi access token (15 phút) hết hạn vẫn vào la
bàn. Nguyên nhân: `/v1/session/refresh` trả 403 `thiet-bi-bi-cam` -> SDK chỉ trả lỗi, `/v1/status` không bao giờ được gọi
nên app không biết trạng thái `banned` (chặn phía server vẫn đúng: mọi API nhạy cảm đều 403). Sửa: `DichVuDinhDanh.tinhTrang()`
coi 403 cấm khi làm mới là `banned` (server quyết) + REF tính từ id thiết bị cùng công thức Worker; đăng ký bị cấm ->
`dinhDanh.biCam` (dừng thử lại). Kiểm lại trên M32 bằng bản đóng gói lại của mã mới: lần đầu băng "hạn chế" (`restricted`),
mở lại -> màn khoá (FLAG_SECURE, chụp màn hình ra ảnh trống); để token hết hạn > 1 giờ: AE ghi `refresh 403` rồi
`register 403`, màn khoá `REF-6F6BF-TCRRV` khớp thiết bị `01M6EFHZM0` (banned).

**Giả vị trí, nguồn mới:** bản thử ký thật + test provider: `MOCK_LOCATION` (`location_mock`, nguồn `hopNhat`) tới server
9 s trước tín hiệu freeRASP; server chỉ cộng điểm lần đầu (+20, lần sau 0).

## 5. Ngân sách Spec §15

| Mục | Ngân sách | Số đo | Nguồn | Kết luận |
|---|---|---|---|---|
| Cold start | < 1,2 s | 612-773 ms (A8b); mở bằng App Link 629 ms (R3b) | M32 | ĐẠT |
| FPS / jank | 60 FPS, jank < 1 % | 60 Hz 58 FPS rớt 0,35 %; 90 Hz 86 FPS | A3 (đường vẽ không đổi) | ĐẠT |
| Tải về | < 25 MB | Play arm64 32,4 MB; APK 33,0 MB | R2a | VƯỢT - do freeRASP `libts.so` 12,5 MB, chấp nhận theo Q13 / Q36 |
| Pin | < 3 %/giờ | ~1 %/giờ (30 phút tab La bàn) | A8b | ĐẠT |
| API p95 | < 300 ms | **phía server** (Analytics Engine, 7 ngày, prod): `/v1/health` p50 213 / p95 353 ms, `/v1/status` 1074 / 1852 ms, `/v1/session/refresh` 1605 / 2607 ms, `/v1/events` 1827 / 3718 ms. Staging `/v1/health` 19 / 240 ms | AE `la_ban_su_kien` | **TRƯỢT -> R3c** |
| Cảnh báo SOC | < 1,5 s | 587-1470 ms khi ấm (S6 - S10) | soc-e2e | ĐẠT (sát) |
| Kill-switch | <= 5 s | đạt (S7c / S10) | | ĐẠT |
| Đồng bộ chặn IP | <= 30 s | đạt (S5 / S7) | | ĐẠT |

Đo p95 từ client (`dinh-danh-e2e.mjs --p95=N`) trên máy WSL không dùng được: TCP + TLS tới Cloudflare 1-4 s, nhiều lần
429 / 401 khi lặp nhanh. Số phía server (`double1` = thời gian I/O trong Worker) cho thấy độ trễ nằm ở các lần gọi D1 / Durable
Object (D1 `la-ban` chạy ở APAC, chưa bật read replication) chứ không phải mạng client -> phase R3c.

## 6. Dọn dẹp

- M32: gỡ test provider vị trí, gỡ bản thử / staging, cài lại beta.13 chính thức, dịch vụ vị trí trả về tắt
  (`location_mode` 0), `http_proxy` null. Xoá APK đóng gói lại ở thư mục thử trên Windows.
- Remote Config staging: gói mới `toiThieu` 1 (cùng 5 pin). Prod không đổi.
- D1 prod còn 3 thiết bị thử bị cấm / sạch của R3b (`01M6ECZHZF`, `01M6EFC4XZ`, `01M6EFHZM0` banned; `01M6EMQBRK` clean) -
  giữ làm bằng chứng audit, SOC lọc theo model nếu cần.
